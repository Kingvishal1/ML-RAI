V20 ONE-BALL NEURAL RELEASE TRAINING — EXPERIMENTAL
===================================================

ONE BALL ONLY: pickup (2.5,3.0,1.0), common circle (3.0,3.5), radius 0.5 m.
Requires your existing Ubuntu RoboEnv project, the two .pt models and V4 .npz.
Do not overwrite original V20.

START (in robotnik_arm_task project root after unzipping):
  conda activate comp0245
  bash RUN_V20_RELEASE_TRAIN_AND_TEST.sh

OR INDIVIDUALLY:
  bash RUN_V20_COLLECT_RELEASE_DEMOS.sh
  bash RUN_V20_TRAIN_ONE_BALL_RELEASE.sh
  bash RUN_V20_TEST_ONE_BALL_RELEASE.sh --headless

What is LEARNED in the test:
  * V20 base reaches ball: trained base BC
  * V20 arm reaches ball: trained arm BC
  * V4 neural gripper closes and holds ball: trained V4 network
  * Release-student network predicts 7 arm-joint increments, 6 finger angles,
    and release probability from 37 live sensor features.
  * In student mode, release finger angles are predictions, never overwritten
    with the scripted expert open target. Network output is latched after
    release decision to avoid unpredictable closing as the ball falls.

What is NOT YET LEARNED:
  * Base carry navigation is still V20 expert during one-ball release training.
  * Phase transitions, physical contact and in-circle release safeguards are code.
  * Student chooses release TIMING from the model's release score; no fixed
    release-height trigger. The physical in-circle and speed checks can veto it.
  * Teacher recordings are generated by original scripted expert. This is
    BEHAVIOURAL CLONING, NOT model-free RL and NOT a fully learned V20.

Do not misrepresent this as script-free end-to-end. The immediate milestone is
learned release behaviour at runtime, not fully learned navigation.

This archive DOES NOT contain trained weights; Ubuntu produces checkpoint after
four distinct, physically successful teacher demonstrations are collected.
Check trained_v20_one_ball_release/training_report.json for held-out results.
Check student log for 'V20_RELEASE_STUDENT_ACTION',
'V8_RELEASE_RESULT', 'V20_CIRCULAR_DROP_RESULT', and ground contact.
Only say success when physical landing is verified.

Potential issue: release may fail in closed loop even after low imitation loss.
If so, do NOT modify the physical success flags; collect more diverse demos
or train a better policy.
